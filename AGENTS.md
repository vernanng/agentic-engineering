# Agentic Engineering — real app, local first

- Root is product: [server.py](server.py) (stdlib-only app), [static/index.html](static/index.html) (UI), [check.py](check.py) (gate), [compose.yaml](compose.yaml), [deploy.sh](deploy.sh), [Dockerfile](Dockerfile). `basics/` is frozen reference — never edit for product work. Local only (`http://localhost:8000`) — no cloud/CI without an explicit ask.
- Fast path: `python3 check.py` (gate, must pass) → `./deploy.sh` (gate → Compose build `loop-app:<git-sha>` + `:latest` → `up -d` → health-check `GET /api/task-types` → auto-rollback to previous SHA on failure; manual rollback `IMAGE_TAG=<old-sha> docker compose up -d`). Logs: `docker compose logs -f app`. Status: `docker compose ps`. Stop: `docker compose down` (keeps the `loop-data` volume).
- Bare-metal `python3 server.py` only (no gate/rollback); optional post-commit hook (not installed by default) runs `./deploy.sh`.
- Git: branch per task (never code direct on `main`); merge to `main` first, then deploy — `./deploy.sh` only from `main`.
- Loop: build `in` >> `near` >> `out` (out last; never start a new task type in `out`). Promote after 3 consecutive clean `in` runs / 5 clean `near` runs (manual Promote click; `force:true` bypasses). `out` failure halts the run, writes an `alert` audit entry, and demotes the task type to `near`. Guardrails: 60s run/decision timeout (`RUN_TIMEOUT_S`), template allowlist only (`summarize|classify|report`), 1 MB body cap.
- Tasks: edit `TEMPLATES` in [server.py](server.py) — steps are `(name, confidence, risky)`. Keep `run_step(step_name, text, confidence) -> (output, confidence)`; stdlib only. Input containing `FAIL` always raises (failure-path test hook).
- Executor: `run_step()` calls OpenRouter when `OPENROUTER_API_KEY` is set, else a local stub (no spend). Model must return JSON `{"output", "confidence"}`; any call/parse failure raises `RuntimeError` so the loop pause/alert handling engages.
- Models (env, read in [server.py](server.py)): `OPENROUTER_MODEL` (default `openai/gpt-4o-mini`); escalates to `OPENROUTER_ESCALATION_MODEL` (default `openai/gpt-4o`) when template confidence < 0.7 (`CONF_THRESHOLD`). Cap via `OPENROUTER_MAX_TOKENS` (default 500). [check.py](check.py) mocks OpenRouter and strips the key for its test server (port 18099, temp DB) — never spend in the gate.
- API (`/api/*`, JSON): `GET /api/task-types`, `POST /api/task-types`, `POST /api/task-types/:id/mode`, `POST /api/task-types/:id/promote`, `GET /api/runs` (latest 50), `POST /api/runs`, `GET /api/runs/:id` (run + steps + audit), `POST /api/runs/:id/decide` (`approve`/`reject`, optional `edited_output`), `POST /api/runs/:id/control` (`pause`/`resume`/`kill`), `DELETE /api/runs/:id` (finished runs only), `GET /api/audit` (latest 100).
- Data/secrets: state is one SQLite file — `loop.db` locally, `/data/loop.db` in the container (`LOOP_DB`), persisted in the external `loop-data` volume. Never `docker volume rm loop-data`, never edit the DB by hand; back up the volume before schema changes. On restart, stale live runs are marked `killed` (stale steps `rejected`); no runner threads survive a restart. Secrets via env/`.env` only (gitignored, see [.env.example](.env.example)), never commit. `LOOP_TOKEN` stays unset while localhost-only; when set, `/api` requires `X-Loop-Token` (or `Authorization: Bearer …`; UI: `localStorage.setItem("loop_token", "<secret>")` then reload).
- Server binds `HOST=localhost` by default; [Dockerfile](Dockerfile) sets `HOST=0.0.0.0` so `-p 8000:8000` can reach it. `PORT` default 8000.
- Docker: one context only (Colima or Desktop) — verify `docker info` before deploy.
- shortcut: with a key set, run inputs are sent to OpenRouter/third-party models — never send confidential input until a data policy is chosen.
- shortcut: [server.py](server.py) uses one SQLite connection + lock for all runs; upgrade to per-thread connections when parallel `out` runs matter.
